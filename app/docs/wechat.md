# 微信聊天（实验）

**用户已确认文件传输助手的兼容发送测试成功，自动读取尚未恢复。** 2026-11-03 曾成功读取真实会话列表，随后切换会话验证时，原微信出现账号安全重新登录提示，原因未确认。当前版本已去掉自动点击切换微信会话；控件不可识别时停止自动轮询，改用人工核对的兼容发送。群聊发送沿用这条路径，尚未进行真实群聊发送验收。

沿用 QQ 的独立聊天页面：左侧搜索、勾选会话和「完成并进入聊天」，右侧显示消息、输入框、总结和个人待办。通过 macOS 辅助功能访问已登录的原微信窗口，不安装微信插件，不修改客户端、签名、数据库或登录数据，也不创建第二个微信会话。

点击「连接微信」后，由用户完成系统辅助功能授权。Dela 只列出原微信已经加载的会话；勾选后，读取该会话在原窗口中的最近最多 200 个可访问消息节点。每两秒刷新，离开页面后停止。当前版本不保存聊天历史和订阅，重新进入需重新连接。微信未提供可识别控件时明确显示兼容性状态，不推断登录状态。这里可能包含时间分隔符、系统通知、媒体占位，不代表完整历史或后台多群同步；发送者、发送时间及未提供的正文不会被推测补齐。

先在原微信打开目标会话，再在 Dela 选择同一会话。Dela 不自动切换原微信。发送文字使用原输入框和发送按键，操作时可能短暂激活原微信；已有微信草稿或接收会话变化时停止发送，未确认提交时保留 Dela 草稿，不自动重试。输入框清空只能说明原微信已处理提交，不能保证服务端送达。图片、表情原文件和附件下载仍在原微信中完成。

## 群聊与兼容发送

控件不可识别时，左侧可以手动添加群名、搜索和选择本地会话入口，各群草稿独立保存在本机。添加群名不会加入群或建立微信身份绑定；同名群需在原微信核对成员。当前不能自动读取群列表、群消息或后台同步，因此没有聊天记录时不显示模拟消息，也不提供基于缺失消息的总结。

先在原微信打开目标群或文件传输助手并点击空白输入框，再从 Dela 填入单行文字。这一步使用系统粘贴，不按发送键。剪贴板的原有格式与内容只暂存于内存，完成后恢复；若期间用户主动复制了新内容，则保留新内容，不覆盖。Dela 无法自动确认接收方和输入结果，必须人工核对原微信的接收方、完整草稿以及附件状态，才能从工作台提交发送键。

准备与提交分为两个操作。发送确认绑定发起窗口和本地会话，并只能消费一次；核对期间锁定本地会话切换。取消、离开页面或提交后都不能重放同一确认，发送异常时也不自动重试。发送键提交后只显示等待核对，不声称消息送达；由用户在原微信确认结果。取消确认不删除原微信中的草稿。兼容模式不能替代自动读取、群过滤或后台同步。

系统画面诊断使用 ScreenCaptureKit，仅针对微信窗口，画面临时保存在内存中。增强辅助功能、窗口内容、可见子节点和导航顺序分别读取；权限具备不代表微信会返回聊天控件。

AI 总结先创建用户可检查的草稿，不自动调用模型。消息可保存为个人待办，备注包含会话、读取时间和可见原文；读取时间不是发送时间。聊天消息视为外部资料。

## 验证和预览

当前适配根据本机微信窗口的辅助功能控件建立，仅支持 macOS。微信版本变化、窗口最小化、弹窗、会话未加载等可能限制读取和交互；没有找到对应窗口时应显示未就绪状态，不能据此判断账号已退出。

`pnpm smoke:wechat` 使用合成桥接数据验证独立布局、授权引导、选会话、发送、真实本地待办、总结草稿、离开后停止读取及四档宽度。它不向真实微信发送消息，不能代替原生收发验收。单元测试覆盖快照校验、重复文本的消息标识和总结范围。

构建需要 macOS Command Line Tools，Vite 会编译 `src/main/wechat/native/accessibility.swift`。`pnpm preview:wechat` 或 `node scripts/run-ts-smoke.ts wechat-preview` 使用 `.build/wechat-preview` 中的独立数据目录，不覆盖已安装 QQ 版。兼容发送的用户实测成功不代表自动读取控件或群聊自动绑定已恢复。

旧工作台布局中的窗口镜像标签保留兼容，新侧栏入口直接打开微信聊天页。

## 只读数据库预览

数据库模式以「JLU-Dela」为白名单，只有精确匹配到唯一的真实 `@chatroom` 标识才读取消息。同名群或未找到群时停止。每 5 秒读取本机最新最多 200 条，工作台保留最多 500 条去重缓存；消息标识包含账号、群、数据库分片和本地消息 ID。它不是全量历史备份，繁忙群在两次轮询之间超过读取窗口的消息可能遗漏。离开群页后停止轮询，已开始的单次读取可以完成。

本地预览通过独立 Python 进程调用 [Rion Reader](https://github.com/Rion-Wu-tech/wechat-intelligence-hub/tree/fb6a42c34160d2ffa66ed5f114f8d8cdabe7f5f9/projects/rion-wechat-reader)，保留其许可证；未将第三方 Reader 源码入库或捆绑到已安装 QQ 版。运行 `node scripts/prepare-wechat-reader.ts` 在本项目 `.build` 中准备固定源码、SQLCipher 和 Zstandard。该步骤不获取密钥、不安装 Skill、不修改或重启微信。此运行环境尚未制作成发行包。

读取使用本人 `~/.config/rion-wechat-reader/config.json` 中已有的授权数据库与访问材料。Reader 将数据库及 WAL/SHM 复制到私有临时目录，再以只读连接查询；不写原微信目录。缓存只保存目标群消息，在当前 Dela 数据目录中以本人权限写入。密钥不经过 renderer、命令行参数或日志。媒体暂时只显示类型提示，不代表已下载附件。

2026-11-03，本机两个账号目录内检查到的 36 个数据库均为加密格式，约定位置没有已有访问材料；普通权限的进程访问检查被系统拒绝，未读取进程内存。Rion 的实验性首次取钥候选涉及退出微信、重签名临时副本及调试访问，不属于本次保持微信客户端不动的实现范围，未执行。**真实 JLU-Dela 群消息仍未同步。** 加密虚构数据测试已覆盖群白名单、schema-2 密钥、WCDB 压缩、WAL 新消息、分片标识、重复读取及源文件不变；不能据此宣称本机真实数据库已解密。

数据库回归：`.build/wechat-reader/venv/bin/python src/main/wechat/test/database_smoke.py`；缓存单元测试在 `src/main/wechat/test/database.test.ts`，界面冒烟使用合成桥接数据。

依据：[Apple Accessibility](https://developer.apple.com/documentation/applicationservices/axuielement)。

同类控件缺失问题见[上游复现记录](https://github.com/BiboyQG/WeChat-MCP/issues/8)，该记录涉及的系统版本与本机不完全相同，不能据此断言具体原因。
