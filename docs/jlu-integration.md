# 吉大校园接入计划

首批用户为本科生，首版优先课表、课程资料与通知。先完成 macOS Apple Silicon 工作台，再基于真实样例接入学校服务。

## 当前基础

保留 Dela 的 Electron / React / Pi 工作台。平台入口及接入状态由 `src/shared/jlu.ts` 维护；主界面与 `dela campus_status` 使用同一份清单。当前全部为 `pending`，仅提供跳转，不模拟同步成功或填充演示个人数据。

校园页面由系统浏览器打开，登录由使用者自行完成；当前应用不持有吉大校园会话。上游校园实现保留在源码中供迁移参考，Agent 命令与内置校园技能已停用。未来只复用经确认适用的数据模型和工作台逻辑，不把替换域名视为完成适配。

分享样例前移除密码、Cookie、令牌、学号、姓名、联系方式与个人成绩。优先提供单个脱敏响应或导出文件，避免上传完整浏览器会话和未处理的 HAR。真实样例默认不入公开仓库；测试只使用人工构造且保留结构的 fixtures。

## 接入顺序

1. **课表**：确认本科教务登录与导出能力；按真实结构实现读取或导入，再接入日历。无样例前不承诺某个文件格式已经可导入。
2. **课程资料**：确认课件的真实来源，打通课程 → 文件 → 本地预览 / Agent 引用。回放播放与批量下载单独验收。
3. **通知**：确认可见栏目与正文结构后，实现按需刷新、分页、去重和原文跳转；最后再做后台提醒。
4. **正式分发**：配置项目自己的 Apple Developer 签名、公证与更新产物，验证后发布 GitHub Release。

每项接入都需处理登录失效并明确显示未同步状态。接口实测失败不能覆盖为已同步；学校服务不可用时，本地资料与 Agent 工作台仍应可用。

## 当前不作承诺的能力

- 成绩、培养方案、自动选课及其他教务写入。
- 校务通知的自动抓取与后台推送。
- 课程录像的下载与转写。
- Intel Mac、Windows 和 Linux 的吉大版发行支持。
