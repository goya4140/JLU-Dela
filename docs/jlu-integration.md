# 吉大校园接入计划

首批用户为本科生，首版优先课表、课程资料与通知。先完成 macOS Apple Silicon 工作台，再基于真实样例接入学校服务。

## 当前基础

保留 Dela 的 Electron / React / Pi 工作台。平台入口及接入状态由 `src/shared/jlu.ts` 维护；主界面与 `dela campus_status` 使用同一份清单。教务为 `preview`，课程回放和通知为 `pending`。模拟数据只用于自动化测试，不写入正常用户的数据目录。

教务登录复用 Dela 的独立 Electron Session、学校登录窗口与主进程请求机制；吉大 `jlu.edu.cn` 域的会话 Cookie 在本机保存，会话 Cookie 额外使用 safeStorage 加密保存。应用不读取或保存学校密码，不向 Agent 暴露 Cookie。其他学校平台仍在系统浏览器中打开。

课表沿用上游的 IPC → 领域逻辑 → SQLite → 日历 / Agent 架构。吉大接口、字段、二进制周次、校历和节次单独适配；上游其他校园能力继续停用。

## 接入顺序

1. **课表**：已按公开项目的接口记录实现读取与日历接入；需用户本人登录完成实测。不支持尚未核对的课表文件导入格式。
2. **课程资料**：确认课件的真实来源，打通课程 → 文件 → 本地预览 / Agent 引用。回放播放与批量下载单独验收。
3. **通知**：确认可见栏目与正文结构后，实现按需刷新、分页、去重和原文跳转；最后再做后台提醒。
4. **正式分发**：配置项目自己的 Apple Developer 签名、公证与更新产物，验证后发布 GitHub Release。

每项接入都需处理登录失效并明确显示未同步状态。接口实测失败不能覆盖为已同步；学校服务不可用时，本地资料与 Agent 工作台仍应可用。

- 课程录像的下载与转写。
- Intel Mac、Windows 和 Linux 的吉大版发行支持。

## 课表接口依据与验证状态

参考 Dela 的 `src/main/campus.ts`、`src/main/timetable/api.ts` 和领域命令分层。吉大当前登录入口已在浏览器中确认会跳转至 `cas.jlu.edu.cn/tpass/login`；受保护的课表响应未使用个人账号实测。

接口及字段记录交叉参考 [SuperJLU 的接口清单](https://github.com/Runa-Asahi/SuperJLU/blob/08b00d95331b830d432a600a10c8267234aab291/jlu_toolkit/endpoints.py) 与 [拾光课表的吉大适配](https://github.com/ShiGuangSchedule/shiguang_warehouse/blob/03d161a416db6fa5f5f7835a377821c077b670b4/resources/JLU/JLU_01.js)。实现根据这些接口事实独立编写；它们是网页使用的个人业务接口，并非已取得官方开放平台授权。

| 用途           | `/jwapp/sys/wdkb/modules/` 下的只读查询接口             |
| -------------- | ------------------------------------------------------- |
| 当前学期       | `jshkcb/dqxnxq.do`                                      |
| 整学期课表     | `xskcb/cxxszhxqkb.do`，参数 `XNXQDM`，不传学号或 `SKZC` |
| 校历           | `xskcb/cxxljc.do`，参数 `XN`、`XQ`                      |
| 节次时间       | `jshkcb/jc.do`                                          |
| 调停课         | `xskcb/xsdkkc.do`                                       |
| 未排定时间课程 | `xskcb/xswpkc.do`                                       |

有效课表、校历和节次先完整解析，再在同一个数据库事务中替换目标学期缓存和时间元数据。调停课匹配不到原课程、附加接口失败或未排定时间的课程都会形成持久警告，Agent 不会把这类结果报告为完整覆盖。
