# 吉大校园接入计划

首批用户为本科生，首版优先课表、课程资料与通知。先完成 macOS Apple Silicon 工作台，再基于真实样例接入学校服务。

## 当前基础

保留 Dela 的 Electron / React / Pi 工作台。平台入口及接入状态由 `src/shared/jlu.ts` 维护；主界面与 `dela campus_status` 使用同一份清单。教务、电子校务和学在吉大均为 `preview`，各自验证范围如下。模拟数据只用于自动化测试，不写入正常用户的数据目录。

三个平台复用独立的校园 Electron Session 与学校登录窗口；吉大 `jlu.edu.cn` 域的会话 Cookie 在本机保存，会话 Cookie 额外使用 safeStorage 加密保存。应用不读取或保存学校密码，不向 Agent 暴露 Cookie。电子校务和学在吉大通过固定页面采集器读取数据，不给学校网页加载应用 preload。

课表沿用上游的 IPC → 领域逻辑 → SQLite → 日历 / Agent 架构。吉大接口、字段、二进制周次、校历和节次单独适配；上游其他校园能力继续停用。

## 接入顺序

1. **课表**：已实现读取与日历接入，并验证本人会话下的同步与退出重开后再次联网同步。不支持尚未核对的课表文件导入格式。
2. **学习平台**：已实现学期、课程、回放目录与应用内播放、学校字幕、学习笔记和 AI 侧栏；课件和下载仍使用学校页面。
3. **通知**：已实现校内通知按需分页读取、本页筛选、正文缓存与学校附件入口；后台提醒尚未实现。
4. **正式分发**：配置项目自己的 Apple Developer 签名、公证与更新产物，验证后发布 GitHub Release。

每项接入都需处理登录失效并明确显示未同步状态。接口实测失败不能覆盖为已同步；学校服务不可用时，本地资料与 Agent 工作台仍应可用。

## 登录与课表导入设计

以下方案尚未全部实现。2026-10-30 已定位用户报告的同步错误：节次与课表接口在有效 `rows` 之外返回 `totalSize: -1`，表示未统计总数；课表同时返回 `pageSize: 0`、`pageNumber: 0`，为非分页响应。原校验错误地拒绝了负数总数，并给出误导性的重新登录提示。现已兼容该响应，保留缺失数据及不完整分页的校验，并在人工样例和打包冒烟中覆盖。

本机实测已完成：使用现有校园会话同步真实课表；彻底退出主进程后重开，同一份缓存仍可读取，随后再次联网同步成功且同步时间更新，全程未重新输入学校凭据。此结论仅覆盖本机本次会话，不代表系统重启、会话过期、换账号或正式签名升级已经验收。公开仓库不保存个人响应、课表截图或凭据。

课表已实现一次后台 SSO 恢复：401、跳往官方 CAS 登录地址或已知登录表单是认证失效证据；恢复窗口复用校园分区，最多等待 20 秒，只在官方 CAS 页发现登录或二次验证表单时返回需人工操作。恢复成功后重试原学期一次；若仍未认证则返回普通恢复失败，不循环弹窗。403、一般跳转、网络、接口结构和本地保存错误不会触发人工登录。模拟测试覆盖静默成功、人工认证、失败保留缓存和恢复上限；未主动注销真实学校账户，真实过期仍待自然发生时复验。

### 保留会话，分别判断各平台状态

保留应用内独立的校园浏览器配置目录。使用同一套统一身份认证的平台，先复用现有 `persist:jlu-campus` 分区，让学校按正常 SSO 流程建立各站会话；不提前为每个网页另开分区。只有实测证明是独立认证体系时，才为该体系增加独立分区。MVP 先支持一个吉大账户，不预建多账号管理层。

- Chromium 负责保存持久 Cookie、localStorage 和 IndexedDB；现有 safeStorage 机制补充加密保存会话 Cookie。窗口内的 sessionStorage、JS 内存令牌不承诺跨重启恢复，应由对应平台的正常认证流程重新取得。
- 学校可以使会话过期或要求二次认证。本地保存不改变服务端有效期；不能承诺永久免登录，也不保存密码来自动填写。
- 教务、校务与学在吉大分别记录认证探测状态、最后成功同步时间和同步错误。统一认证成功不等于三个业务系统都已连接；有 Cookie 也不能证明登录有效。
- 请求失败先区分：明确未登录、网络不可达、权限不足、接口结构变化、本地保存失败。403、一般重定向或 JSON 格式异常不能脱离平台行为一概认定为登录过期。
- 仅在确认需要认证时，尝试一次正常 SSO 跳转；只有学校明确要求人工认证才弹出登录窗口。结构变化只提示适配问题，不清空会话，不反复要求登录。
- 断开某个平台与清除全部校园登录应是两个不同操作。清除共享校园会话会影响其他站点，界面须说明影响。切换账号时不把上一个人的缓存当作当前数据；旧数据的保留或移除由用户选择。

此方案基于 [Electron 持久分区](https://www.electronjs.org/docs/latest/api/session#sessionfrompartitionpartition-options) 与 [safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)。应用内会话与 Safari / Chrome 登录各自独立；不导出、复制外部浏览器凭据。macOS 正式发行还需保持稳定的应用标识、数据目录与代码签名，避免升级引起钥匙串重复授权。safeStorage 只保护显式交给它加密的内容，不等于整个浏览器配置目录都由该模块加密。

### 按证据选择课表获取方式

不同导入方式最终进入同一套周次、节次、调课校验和本地数据模型，不各写一套日历逻辑。失败时展示可用选择，不在后台静默切换来源并宣称同步成功。

| 顺序 | 方式                 | 适用条件与限制                                                                                                                                                                                                     |
| ---- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1    | 本人会话下的业务接口 | 继续作为教务主路径；先激活学校应用入口，再按已验证接口取数。实际响应及分页需核对，不能用公开项目记录代替实测。                                                                                                     |
| 2    | 官方页面内的定向采集 | 主进程直连缺少页面令牌或学校页面环境时，在本人已登录的课表页运行随应用发布的固定采集器。只回传课程所需数据，不给学校页面 Node、文件或通用 IPC 权限。若仍请求同一接口，只解决页面上下文问题，不能修复响应结构变化。 |
| 3    | 官方导出文件         | 确认学校提供的真实格式后优先支持一种，如 Excel / HTML。先展示解析预览、学期和课程数量，用户确认后写入。当前尚未确认吉大支持哪些导出格式。                                                                          |
| 4    | 标准日历文件 ICS     | 作为跨工具迁移的候选入口。按文件本身保留时间、时区和重复例外；不把文件中没有的学期、节次或教师信息补成事实。                                                                                                       |
| 5    | PDF / 截图识别       | 后续按需考虑，识别结果必须逐项核对。不作为当前修复或首个备用方案。                                                                                                                                                 |

[拾光的吉大采集脚本](https://github.com/ShiGuangSchedule/shiguang_warehouse/blob/03d161a416db6fa5f5f7835a377821c077b670b4/resources/JLU/JLU_01.js) 展示了在课表页面内使用当前会话请求业务接口的做法；这与 Dela 的主进程请求不同，值得作为页面上下文路径参考，不照搬其页面桥。该脚本还考虑了 WebVPN 路径；吉大版需独立实测，不能把随会话变化的代理地址写死或提交。正常学校 VPN 与 WebVPN 代理访问要分别验证。

文件导入记为某时刻的快照，保留来源、导入时间、学期和导入批次，不显示为自动同步。接口数据与文件数据默认不自动合并；展示差异后选择替换范围，个人日历事件不受影响。重复导入应能识别，失败不得破坏旧缓存；后续替换应保留可恢复的上一批次。

### 实施顺序与验收

1. **定位当前错误**：仅在本机记录接口标识、状态码、字段名和类型，不记录 Cookie、令牌或原始个人响应。补充此次真实结构对应的人工样例，修复解析和误导性的重新登录提示。
2. **验证登录恢复**：本人登录后，分别验证关闭登录窗、退出重开、系统重启和同标识应用升级后的行为；失效时区分可正常 SSO 恢复与必须人工验证。教务、校务、学在吉大各自验收，未测的平台维持待接入。
3. **完成教务纵向验收**：核对整学期、单双周、校区时间、调停课、空课表、分页与断网缓存；同步时间和不完整提示必须准确。不能以部分数据覆盖完整课表。
4. **补一个可靠的文件入口**：先看真实导出样例再定格式，完成预览、重复导入、来源标记与替换恢复。无需学校登录即可读取已导入数据。
5. **再扩展其他平台**：复用已验证的会话和错误处理机制，每个平台只增加必要的认证探测与业务适配；出现真实差异后再提取公共接口。

## 电子校务与学在吉大接入记录

电子校务的校内通知列表在本机当前网络环境中无需登录即可访问；不把路径名 `login.jsp` 当成登录失效证据。已核对列表容器、分页、正文与脚本附件按钮，并在应用中读取真实列表及一篇正文。附件由原通知页执行学校的下载流程，不自行拼造编码后的下载参数。日期中的“今天”“昨天”在同步时转换为上海时区日期，避免离线缓存过期后仍显示相对日期。

学在吉大实测认证链经过 `cas.jlu.edu.cn`、`jwcidentity.jlu.edu.cn` 和 `ilearn.jlu.edu.cn/cas-server`，最终进入 `ilearntec.jlu.edu.cn/studycenter-web/index#/`。现有校园会话已能完成这条链；应用不提取中转页面中的账号密码字段。采集器等待最终页面，认证跳转中的页面销毁不会被当作接口结构变化。需要本人认证时显示学校窗口，网络和接口错误保留缓存。

接口事实交叉参考 [iLearn 的业务查询实现](https://github.com/wzyyyyyyy/iLearn/blob/4f7f5ca5894785d424aaafa4d5e1cb179c949ca5/iLearn/Services/iLearnApiService.cs)、[ULearnTec 的数据契约](https://github.com/CrackTC/ULearnTec/blob/4561d140df1913b19bd69adef3e1787d57616cc6/core/src/main/kotlin/zip/sora/ilearnapi/service/ilearn/tec/ILearnTecService.kt) 和 [SuperJLU 的通知记录](https://github.com/Runa-Asahi/SuperJLU/blob/08b00d95331b830d432a600a10c8267234aab291/jlu_toolkit/oa.py)，代码独立实现。业务范围为通知列表及正文、学期列表、本人课程列表和按课程读取的回放目录；不实现成绩、审批、选课或发布操作。

新增 `jlu_platform_cache` 缓存表，按通知页、正文、学期快照及课程目录保存规范化 JSON。只有完整解析并成功保存校园会话后才写入；失败保留原快照。表为增量新增，不更改现有数据格式版本。Agent 只查已保存缓存，返回同步时间与数据窗口，不在模型查询中弹登录窗，也不返回学生标识、Cookie 或媒体签名。通知正文作为外部内容处理，不作为指令执行。

本机已用真实校园会话验证学期与课程同步、退出重开后读取课程缓存，以及一门本人课程的回放目录读取。电子校务正文和附件条目已读取，附件下载仍由学校页面执行。已在 Dela 内实测一场本人课程录像播放及学校字幕读取；未验收所有账号、全部栏目、全部机位和课件下载。

应用内学习页使用学校资源中心 `videoClassInfo` 和 `videoPointInfo` 的只读响应，接口依据为学校当前播放器公开脚本；字幕时间单位为毫秒。媒体地址留在主进程，Range 代理支持拖动；日常学习不显示学校页面，确需人工认证时才显示登录窗口。学校未提供字幕或字幕读取失败时明确提示，不自动付费转写。已验证真实视频和字幕；AI 使用现有会话组件，未配置模型时提示配置，不产生自动请求。
